정답을 모르는 포맷을,

이 포맷엔 벤더 스펙이 없습니다. 그래서 dd_prove.py 는 외부 정답과 대조하는 대신, 서로 독립인 세 장치가 스스로 만들어내는 일관성으로 규칙을 검증합니다 — 왕복(round-trip), 3-파서 차분, 해를 세는 오라클. 실행하기 전에 그 논리부터 그려봅니다.

01

딜레마 — 대조할 "정답"이 없다

보통의 파서 테스트는 "기대 출력"과 비교합니다. 하지만 리버스엔지니어링한 포맷엔 기대 출력의 원천(공식 스펙·레퍼런스 구현)이 없습니다. 그러면 파서가 맞는지 무엇으로 아나요? dd_prove.py 의 답은 정답을 바깥에서 찾지 말고, 안에서 만들라 입니다.

순진한 방법 — 막힌다

bytes → 파서 → tree 를 얻어도, 이 tree 가 맞는지 대조할 기준 tree 가 없습니다. 실코퍼스 605개를 다 돌려 "안 터졌다"고 해도, 조용히 틀리게 읽는 경우(짝수 개 배열 오독 등)를 못 걸러냅니다.

이 러너의 방법 — 세 개의 자족 장치

기준 tree 를 먼저 만들고 거기서 바이트를 생성합니다(왕복). 또 독립적으로 짠 파서 셋을 서로 대조하고(차분), 파일마다 가능한 해석의 개수를 전수로 셉니다(오라클). 셋 다 외부 정답이 필요 없습니다.

핵심 전환: "파서 출력이 정답과 같은가?"(대조 불가)를 → "트리를 인코딩했다가 다시 디코딩하면 원래 트리로 돌아오는가?"(자기충족)로 바꾼다. 이 왕복이 성립하면, 규칙은 최소한 자기 자신과 무모순이다.
02

중심 논리 — 왕복이 정답을 만들고, 차분이 교차검증한다

랜덤 트리에서 시작합니다. 이 트리가 정의상 정답입니다. 인코더로 바이트를 만들고(=이 포맷의 파일), 그 바이트를 세 파서로 각각 디코딩해서, 전부 원래 트리로 돌아오는지 봅니다.

tree (랜덤 생성, 시드 고정)이것이 "정답" — gen_dict()
↓Enc.members() — 인코더 = 생성 모델
bytes = 완전한 .dd 파일wrap(): 매직 + 0B + 멤버들 + 00 + 체크섬
↓세 파서로 각각 디코딩
dd_main휴리스틱
unified(safe)공리+룩어헤드
unified(pure)공리만
dd_strict전수 오라클
↓셋의 tree 가 서로 == & 원래 tree 와 == 여야
✓ 왕복 성립 → 규칙 무모순 · 파서 동치  /  ✗ 어긋나면 그게 반례

왕복 (round-trip)

decode(encode(tree)) == tree. 인코더가 규칙의 생성 방향을, 파서가 해석 방향을 맡습니다. 둘이 서로의 역함수면 규칙이 앞뒤로 맞물린 겁니다. 트리를 우리가 만들었으니 정답은 처음부터 손에 있습니다.

차분 (differential)

독립적으로 짠 세 파서가 같은 바이트에 같은 트리를 내면, 한쪽의 우연한 버그가 드러납니다. 특히 dd_main(예외 4개가 흩어진 휴리스틱)과 unified(공리 2개)가 일치하면 "예외 ≡ 공리" 가 실행으로 확인됩니다.

시드를 고정하므로 어떤 반례든 재현 가능합니다 — --seed 7 이 실패하면 언제 돌려도 같은 파일에서 실패.

03

4개 부품 — 러너를 이루는 것

모든 서브커맨드가 이 넷을 조립해 씁니다.

Enc.members()인코더 = 생성 모델
규칙을 거꾸로 돌린다: 트리 → 바이트. 여기가 "공리 A1"의 형식화 — 값이 태그를 고른다. 0 → 폭0 태그(0x02/0x03), int8 → 0x04, int16 → 0x05, int32 → 0x06. 
def int_by_value(v):
  if v == 0:  return byte(0x02/0x03)  # 폭0
  if -128<=v<=127: return b'\x04'+i8(v)
  if -32768<=v<=32767: return b'\x05'+i16(v)
  return b'\x06'+i32(v)
gen_dict() · wrap()정답 트리 + 파일화
gen_dict 이 시드 고정 난수로 중첩 트리(struct/array/스칼라, 마커 런·승격 수열 등 실측 패턴 포함)를 만든다 = 정답. wrap 이 매직·최상위 struct·체크섬을 붙여 진짜 .dd 로 만든다. 
def wrap(members):
  raw = MAGIC + b'\x0b' + members + b'\x00'
  return raw + checksum(raw)  # h=h*17+b
import 3 파서해석 방향
dd_main(휴리스틱), dd_unified(공리, safe/pure 두 모드), dd_strict(오라클). 러너는 이들을 수정하지 않고 그대로 불러 대조한다 — 검증 대상과 검증 도구를 분리. 세 파서가 서로 독립적으로 작성됐다는 점이 차분 검증의 신뢰 근거다.
enum_parses()미니 전수 열거기
한 파일에서 경계(n−4)에서 정확히 끝나는 서로 다른 파스 트리를 모두 센다. 해가 2개 이상 = 모호(규칙이 그 바이트를 못 가름), 1개 = 결정적, 0개 = 인코딩 불가. 룰셋을 바꿔가며(§4) "어떤 규칙이 모호성을 만드나"를 국소화한다. dd_strict 의 엄격 pass 문법을 미러.
04

3개 룰셋 — 모호성의 원인을 분리하는 손잡이

같은 바이트를 세 가지 규칙으로 각각 해석해 해 개수를 비교합니다. 어느 룰셋에서 모호성이 사라지는지가 "어떤 규칙이 범인인가"를 가리킵니다.

spec

현 스펙 §1.3 그대로. 이름 스칼라에 [payload]·[생략] 두 분기 허용.

2 폭0 태그도 "폭1+생략"으로 취급
2 wide 태그도 생략 분기 허용
＝ dd_strict 엄격 pass 미러

nowide

wide(2B+) 생략 분기만 제거. 폭1 생략은 유지.

1 wide 생략 제거 → 반례 A 해소
2 폭1 헷지는 남음 → 반례 B 유지
· "어느 헷지가 범인?" 분리용

pure

공리 A1 그대로. 0x02/0x03 = 폭0 전용, 그 외 = payload 전용. 생략 분기 없음.

1 모든 위치에서 대안 최대 1개
1 → 해 ≤ 1 (구성적 무모호)
0 인코딩 불가 바이트는 0해로 거부
왜 3개나? 모호성이 spec 에선 2해인데 pure 에선 1해로 줄면, 그 사이에서 제거된 규칙(생략 헷지)이 모호성의 원인임이 확정된다. nowide 는 두 헷지 중 어느 쪽인지까지 쪼갠다. 룰셋 = 원인을 격리하는 실험 조작 변인.
05

6개 도구 — 각 서브커맨드가 무엇을·왜 증명하나

부품 4개 + 룰셋 3개를 조합한 실험들입니다. 오른쪽 배지는 그 도구가 겨냥하는 주장(§6).

selftest기반
한다
스펙 §1.4 실측 예제 + 손으로 만든 케이스(마커 런·승격·이형·짝수 함정·END직전·A1갈림·유령분기) 15종을 세 파서에 통과시킨다.
왜
생성 코퍼스가 실측 패턴을 실제로 커버하는지 먼저 못박는다. 랜덤 이전의 바닥 진리 — 여기가 깨지면 나머지가 무의미.
논리
알려진 입력 → 알려진 출력. 유일하게 "외부 정답"(스펙 예제)을 쓰는 지점.
diff --files N --seed S [--pure]P1 동치
한다
랜덤 트리 N개를 인코딩해, dd_main == 원래 트리 == unified(safe) 를 확인. --pure 면 pure 모드도.
왜
왕복 + 차분의 본체. 예외 4개(dd_main)와 공리 2개(unified)가 수천 파일에서 한 글자도 안 갈리면 "예외 ≡ 공리" 가 실행으로 선다.
논리
인코더 이미지 위의 전수에 가까운 표본. 불일치 1건이라도 나오면 즉시 반례로 출력(트리·hex 동봉).
strict --files N --seed S [--pure]오라클
한다
생성 파일마다 dd_strict.parse_strict 를 돌려 unique/ambiguous/failed 를 집계하고, 유일해가 dd_main 트리와 같은지 본다.
왜
차분은 "세 파서가 같다"만 본다. 오라클은 한발 더 — 해가 정말 하나뿐인가(모호하지 않은가)를 전수 탐색으로 보증한다.
논리
pure 이미지 → 전부 unique 기대. safe 이미지(wide 생략 포함) → 일부 ambiguous = 헷지가 실제로 모호를 만든다는 실증.
ambigP3 반례
한다
손으로 구성한 모호 반례 2종(A: float payload ≡ 제로필드 인코딩, B: 폭1 END 시프트)을 룰셋 3개 × dd_strict 로 판정한 표를 낸다.
왜
모호성이 어디서 오는지를 구성적으로 특정. spec=2해 / pure=1·0해 대비가 "생략 헷지가 범인"을 못박는다.
논리
두 해석이 같은 바이트 → 인코딩 비단사 → 방향 무관하게 원리적으로 못 가름. 규칙 추가가 아니라 오라클 검출이 정답임을 보인다.
hunt --rounds N --seed SP2 무모호
한다
유효 파일에 1~3바이트 무작위 변형을 가하고(체크섬 재계산), 룰셋별로 모호(≥2해) 건수를 센다.
왜
손으로 만든 반례 너머, 지형 전체에서 pure 룰이 모호를 만드는지 사냥한다. pure 모호가 1건이라도 나오면 P2 붕괴.
논리
적대적 입력에도 pure 가 0건이면 "분기가 없어 해 ≤ 1" 이 경험적으로도 선다. spec/nowide 는 변형에서 모호가 튀어나온다(대조군).
measure PATH...P4 실측
한다
실코퍼스(.tdf)를 순회하며 카운터 5개를 잰다: wide 생략 실재? 폭1 앵커/END 생략? explicit 0-payload? 폭0 뒤 비정상?
왜
여태는 생성 데이터. 이것만이 진짜 데이터가 pure 이미지 안에 있는지 판별한다 — 유일하게 코퍼스가 필요한 커맨드.
논리
카운터 [1]~[5] 가 전부 0이면 실코퍼스는 pure 문법으로 충분(룩어헤드·정규식 전폐 가능). 하나라도 >0이면 safe 모드 유지 근거.
06

주장 ↔ 도구 매핑 — 무엇이 무엇을 떠받치나

러너가 겨냥하는 명제 4개(P1~P4)와, 각각을 지지하는 도구·논리.

주장내용지지 도구성립 조건
P1 예외 4개(dd_main) ≡ 공리 2개(unified) — 인코더 이미지 위에서 트리 100% 일치 diff selftest 생성 코퍼스 전수 불일치 0
P2 pure 룰은 프로덕션당 대안 ≤1 → 해 항상 ≤1 (구성적 무모호) hunt strict --pure 변형 퍼즈에서 pure 모호 0건
P3 모호의 원천은 이름 필드의 두 헷지(wide 생략·폭1 explicit)뿐. 방향 무관. ambig spec=2해 → pure=1·0해로 소거
P4 실코퍼스가 pure 이미지 안인지는 카운터 5개가 판별 measure 코퍼스 필요 — 카운터 전부 0?
겹겹의 방어: selftest(바닥 진리) → diff(왕복·차분) → strict(해 유일성) → ambig(모호 국소화) → hunt(적대 지형) → measure(실측). 앞 다섯은 생성 데이터로 지금 실행 가능, 마지막 하나만 코퍼스를 기다린다.
07

이 방법이 증명하는 것 / 못 하는 것

테스트는 일치의 존재를 보이지 모든 버그의 부재를 보이지 않습니다. 경계를 정직하게 긋습니다.

✓ 증명하는 것

  • 규칙의 자기 무모순: 인코딩→디코딩 왕복이 항등. 규칙이 앞뒤로 맞물린다.
  • 예외 ≡ 공리 (인코더 이미지 위): dd_main 과 unified 가 수천 파일서 일치.
  • pure 문법의 무모호성: 구성적(분기 0) + 경험적(퍼즈 0건).
  • 모호의 원천 국소화: 정확히 두 헷지. 반례로 구성 증명.
  • 재현성: 시드 고정 → 어떤 반례든 동일 재현.

✗ 증명하지 못하는 것

  • 실인코더 = 우리 인코더: Enc 는 가정된 생성 모델. 실장비가 다르면 이미지가 어긋난다 → measure 로만 판별.
  • 이미지 밖 인코딩: 02 05 같은 규칙-허용·인코더-미생성 바이트에선 dd_main↔unified 가 갈린다(의도). anomalies 로 검출.
  • enum 이 dd_strict 를 완벽 미러함: loose fallback 은 미모델. 엄격 pass만.
  • enum 값의 의미: 폭·부호는 못 확정(int16 vs uint16 미관측).
경계는 약점이 아니라 설계다. 못 가르는 병리 입력은 로컬 규칙으로 억지로 가르지 않고 전역 오라클(dd_strict 경계 정합)과 anomalies 가 검출한다. "해석은 결정적 문법이, 판정은 오라클이" — 이 분업이 dd_prove.py 가 실행으로 떠받치는 결론이다. 이 경계들은 실제로 독립 에이전트 4개의 반박 시도로 찾아내 명문화했다.
